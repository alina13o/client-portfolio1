# Прототип анализа клиентского портфеля

Django-прототип для дипломной работы: хранение клиентского портфеля в PostgreSQL, загрузка Excel, сравнение произвольных периодов и формирование управленческих рекомендаций.

## Стек

- Django 5
- PostgreSQL 18
- pandas + openpyxl для импорта Excel
- встроенная Django-аутентификация: логин, пароль, группы, админка

## Запуск локально

1. Создать окружение и поставить зависимости:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

2. Запустить PostgreSQL:

```bash
docker compose up -d
```

Если PostgreSQL уже установлен локально, создайте БД и пользователя с параметрами из `.env.example`.

3. Применить миграции:

```bash
.venv/bin/python manage.py migrate
```

4. Создать владельца системы:

```bash
.venv/bin/python manage.py createsuperuser
```

Или загрузить демонстрационные учетные записи:

```bash
.venv/bin/python manage.py seed_demo
```

Демо-логины: `owner / owner123`, `maria / maria123`.

5. Запустить сайт:

```bash
.venv/bin/python manage.py runserver
```

Сайт: http://127.0.0.1:8000/

Основные разделы:

- `/manager/dashboard/` — главная страница менеджера.
- `/owner/dashboard/` — главная страница владельца.
- `/owner/dashboard/manager/<id>/` — просмотр портфеля менеджера владельцем в режиме View Only.
- `/clients/` — поиск и список клиентов.
- `/clients/<id>/` — карточка клиента с заказами и помесячной динамикой.

## Роли доступа

- Владелец: `is_staff`, `is_superuser` или группа `owner` / `admin`.
- Менеджер: обычный пользователь, связанный с записью `Manager` через поле `user`.
- Менеджер видит только клиентов, закрепленных за ним в `ClientManagerAssignment`.

## Импорт Excel

Основной формат: одна строка = один заказ.

Ожидаемые колонки:

- `Менеджер`
- `Код клиента`
- `Название клиента`
- `Дата заказа`
- `Сумма заказа`
- `Количество позиций`
- `Категория товара/услуги`
- `Статус клиента`
- `Примечание`

Для старых файлов с помесячным портфелем система пытается импортировать агрегированные суммы в `ClientPeriodFact`.

## Аналитика

Дашборд сравнивает два периода и считает:

- выручку;
- количество активных клиентов;
- retention;
- churn;
- изменение выручки по клиентам;
- сегмент и рекомендацию.

SQL-примеры для дипломного описания общих итогов и сравнения периодов лежат в `docs/sql_queries.sql`.

## Постоянная публичная ссылка через Render

Временные tunnel-ссылки работают только пока включен ваш компьютер. Чтобы сайт открывался у других людей даже при выключенном компьютере, приложение и PostgreSQL должны быть размещены в облаке. Для прототипа подготовлен деплой на Render.

### 1. Подготовить репозиторий

Загрузите проект в GitHub/GitLab. Файл Excel с реальными клиентами не коммитьте: `*.xlsx` добавлен в `.gitignore`.

### 2. Создать сервис в Render

1. Откройте Render и выберите **New + → Blueprint**.
2. Подключите репозиторий с проектом.
3. Render прочитает `render.yaml` и создаст:
   - web-сервис Django;
   - PostgreSQL-базу данных;
   - переменные окружения для подключения к БД.
4. После деплоя постоянная ссылка будет в карточке web-сервиса, например:
   `https://client-portfolio.onrender.com`.

### 3. Проверить вход

Во время сборки создаются учетные записи:

- владелец: `owner / owner123`;
- менеджер: `maria / maria123`.

Перед передачей ссылки другим людям смените пароли через админку Django.

### 4. Загрузить реальные данные

После первого деплоя откройте сайт по ссылке Render и загрузите файл Excel через раздел **Загрузка Excel**. Если нужен чистый импорт без дублей через консоль Render Shell, выполните:

```bash
python manage.py reset_import_portfolio "Портфель Марии Викторовны.xlsx"
```

Команда полностью очищает бизнес-данные и заново импортирует портфель Марии из указанного Excel-файла.

### 5. Production-настройки

Для Render используются:

- `DJANGO_DEBUG=False`;
- `DJANGO_ALLOWED_HOSTS=.onrender.com`;
- `CSRF_TRUSTED_ORIGINS=https://*.onrender.com`;
- `DATABASE_URL` от PostgreSQL Render;
- `gunicorn` как сервер приложения;
- `WhiteNoise` для статических файлов.
